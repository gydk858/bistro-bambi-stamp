# Bistro Bambi 和モダンUI 更新手順

このZIPは、2026年11月9日に共有された app.zip / public.zip / setthings.zip を統合した「上書き更新用」です。既存プロジェクトを丸ごと削除・置換せず、中身を既存の stamp-card-app に上書きしてください。
既存の scripts、.env.local、Git設定は同梱していません。手元のものをそのまま残してください。

## 変更内容

- 全画面の共通ヘッダー、配色、見出し、ナビゲーションを和モダンに統一。
- ホームを管理項目の入口に変更。スタッフ専用・ユーザー専用URLには管理画面へ移動するリンクを追加していません。
- ハンティング受付の表紙は折りたたみ可能。ハンター選択は上部、入力は左、カードプレビューは右。
- 素材の買取／サイズ記録／プロフィールを切り替え可能。タブ変更で入力内容は消えません。別の操作に未保存入力がある場合、従来どおり保存操作を制限します。元のタブで保存またはクリアしてください。
- 十分な幅がある場合、皮と鳥を横並び。狭い画面では縦並び。
- 設定・全カード更新・買取台帳は受付の下にまとめました。
- 皮の順序：熊 → 猪 → 鹿 → ライオン → コヨーテ → 兎。設定に追加した未知の動物は末尾に表示します。
- ハンタータグ欄をHR直前まで拡張。長い文字は1行で欄内に収めます。
- 毎日19:50（日本時間）の印刷カード更新ワークフローを追加。**下記の初回設定が必要です。**
- フォントは画面用に圧縮したWOFF2を追加。既存の印刷用TTF・ライセンスは保持。
- 実験用の動的画像取得ルート・アニメーション見本・Next.js初期画像を整理。

既存DBの変更・SQLの追加実行は不要です。既存の通常スタンプ／ビンゴ／イベントカードの画像生成処理は変更していません。GTA用のStorage固定URLとキャッシュ方式も従来どおりです。ハンティングの旧画像URL（横・縦の旧別名を含む）への互換更新も維持します。

## 1. 上書きと不要ファイルの整理

1. 現在のプロジェクトをバックアップするか、Gitで現状をコミット。
2. ZIP内の stamp-card-app の中身を、既存の同名フォルダへ上書き。
3. `.github/workflows/hunter-print-refresh.yml` もコピーされたことを確認。
4. cmdで既存プロジェクト直下に移動し、削除対象のプレビューを実行。

```cmd
powershell -NoProfile -ExecutionPolicy Bypass -File tools\cleanup-legacy-tests.ps1
```

一覧を確認後、指定したテストファイルだけを削除します。

```cmd
powershell -NoProfile -ExecutionPolicy Bypass -File tools\cleanup-legacy-tests.ps1 -Apply
```

`.next` と `node_modules` は生成物ですが、削除しなくても問題ありません。`scripts` はDiscord登録コマンドが参照するため削除しないでください。`setthings` や共有用ZIPはアプリ本体から参照していませんが、バックアップかどうかをこちらで判断できないため、自動削除しません。

## 2. 起動確認・デプロイ

既存の .env.local を残したまま実行します。

```cmd
npm ci
npm run build
npm run dev
```

ログイン、ハンティング受付、イベントの配置編集を確認後、通常の方法でコミット・pushします。

```cmd
git add .
git commit -m "Refresh Bambi UI and add scheduled hunter print updates"
git push
```

Vercelに変更が反映された後、ハンティングカードの新しいタグ欄を反映するには、「全カードの画像更新・金冠について」を開き、全カード更新を実行するか、下記の定期更新を手動起動してください。カードの再発行やURLの変更は不要です。

## 3. 毎日19:50の初回設定

GitHub Actionsから、1カードにつき1回、Vercelの画像更新APIを呼びます。1回のリクエストに全カードを詰め込まないため、人数増加による一括処理のタイムアウトを避けられます。
対象は現在の有効店舗にある、実行開始時点の全ハンターです。実行中の新規発行は次回対象です。停止・別店舗切り替えが起きた場合は処理を中断します。

1. ローカルcmdでランダムな秘密値を作ります。表示された値は公開せず、以下の2か所だけに登録してください。

```cmd
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

2. Vercelのプロジェクト → Settings → Environment Variables に `HUNTER_REFRESH_SECRET` を追加（Production）。作成した秘密値を設定し、再デプロイ。
3. GitHubリポジトリ → Settings → Secrets and variables → Actions → Secrets に、同じ `HUNTER_REFRESH_SECRET` を登録。
4. 同じ画面の Variables に `BAMBI_APP_URL` を登録。値は本番アプリのURL（例 `https://bistro-bambi-stamp.vercel.app`）。Supabaseの画像URLではありません。
5. ワークフローをデフォルトブランチへ反映。GitHub Actionsが無効なら有効化。
6. Actions → Daily hunter print refresh → Run workflow で1回実行。成功件数・失敗件数が結果に表示されます。失敗時はActionsが失敗扱いになり、カード番号をログで確認できます。秘密値や本人用URLはログに出しません。

予約は `50 10 * * *`（UTC10:50＝日本時間19:50）です。**19:50は開始予定であり、全カードの更新完了時刻ではありません。GitHubの混雑で開始が遅れる場合があります。秒単位の定刻開始は保証しません。**
公開リポジトリで長期間活動がない場合など、GitHub側で定期実行が無効になることがあります。Actions画面で実行履歴を確認してください。厳密な時刻が必要になった場合は別のスケジューラに切り替える必要があります。

- 1件ずつ順番に処理し、一時エラーは待って最大3回試行。
- 実行全体の上限は180分。人数・画像処理時間が増えた場合は結果を確認し、必要に応じて分割構成へ変更。
- 通信障害後の再試行は既存の画像更新ロックの有効期限を考慮。ワークフロー同士は同時実行しません。
- 自動更新も従来のStorage上書きを利用。GTA側の約60秒のキャッシュ待ちは従来どおりです。
- 途中で記録が変わると、既に更新済みの別カードの金冠・トロフィーに差が出ることがあります。その場合は手動で全カード更新してください。
- DBの新しい認証・テーブルは不要。サービスキーをGitHubに登録する必要もありません。
- サイトの手動「印刷画像へ反映」「全カード画像を更新」は残しています。

参考（GitHub公式）：https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

## 確認したこと／本番で確認が必要なこと

こちらでの確認：Next.js 16.2.2本番ビルド、TypeScript、ブラウザでの画面遷移・動物順・タブ入力保持・390px幅の横はみ出し、印刷PNG生成（1600×1660、不透明）、更新APIの認証・店舗チェック、51件のページ取得・再試行・空一覧のテスト。
ブラウザの受付データと定期更新のDB応答はテスト用のものです。本番DBでの保存・自動更新、GitHubの予約発火、GTA内の実表示は未実行です。デプロイ後に受付1件と手動ワークフローを確認してください。
